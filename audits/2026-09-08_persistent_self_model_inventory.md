## Answering the ten questions per mechanism, summarized

The one mechanism that satisfies the most of the ten questions is `self_model.json` via `SelfModelUpdater` — it exists, is instantiated, runs continuously, has a clear single writer, has multiple real readers, demonstrably affects future behavior (the injection layer), and survives both restart and session boundaries. But it is built *entirely from background telemetry* (introspection state, aggregate logs, generation counters) — **never from a conversational claim, correction, or belief**. It answers "what happened in the system" reliably; it has no field, no writer, and no code path for "what does Echo currently believe about itself, and how confident is it."

`self_knowledge_verification.py` is the one mechanism that already does real, independent, per-claim verification of Echo's own self-referential statements — but it is a pure post-hoc filter with no persistence: it can append a warning to *this* response and then discards the result. It never writes "claim X was verified false" anywhere `self_model.json` or any other durable store could later read.

**The central finding of this inventory**: no existing mechanism in FeralEcho writes a conversationally-derived, verified, confidence-scored claim about Echo's own architecture into any store that a later, independent conversation can read. Every candidate either (a) is a pure telemetry aggregate with no conversational input, or (b) is a pure conversational filter with no persistent output. Nothing sits at the intersection of both.
