*Item #17 (Dissent Log gating power): left advisory-only, permanently. Reasoning beyond WOLF's cautionary history: `council_baseline_trusted_since`'s graduated-trust pattern works because River-blend training runs continuously and automatically with no human reviewing each data point — trust-gating is the only practical safety valve at that scale. The Dissent Log isn't that shape of problem. `propose_core_edit()` is already human-invoked-only (`!propose`), runs rarely, and produces a `.patch` a human already has to manually read and apply — by the time gating power would matter, a human is already standing there with the full diff and the council's votes and reasoning in front of them. There's also no clean way to earn trust here the way council ratings could: a rejected proposal never gets applied, so there's no safe way to check "was that rejection actually correct" without either applying rejected changes anyway (defeats the purpose) or trusting the same human judgment the mechanism would eventually replace.*

*Item #18 (curiosity_engine's one-directional WorldModel read): left open, deliberately. WorldModel's value is being a real signal about the external world, fed only by actual fetched news text right now. Closing the loop would mean Echo's own generated content starts shaping what she considers "well-covered" territory, with no clean boundary between "the world told me this" and "I told myself this" — nearly the same shape as two bugs this project already found and fixed (Finding 11's six-day self-quoting loop, Finding 35's dream-synthesis-escaping-exclusion bug). The plausible benefit (avoid re-exploring already-covered internal topics) is already handled by `garden_manager.py`'s own resolution-score/recency weighting, a real, separately-confirmed closed loop — so closing this second loop would add contamination risk for a benefit that's likely already covered elsewhere.*
