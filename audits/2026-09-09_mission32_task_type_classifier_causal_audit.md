# Mission 32 — Adversarial Causal Audit of `task_type_classifier.py`

**Date:** 2026-09-09
**Type:** Investigation-only (bounded, read-only experiments; no production code changed)

## Executive Verdict

`task_type_classifier.py` is a real, genuinely-trained, genuinely-persisted online classifier that is capable of overriding the static keyword heuristic's routing decision (VERIFIED, via a controlled ablation experiment against the real persisted model). But its training signal is, for 99.5% of the real training corpus currently on disk, mechanically and provably traceable to the very same static keyword heuristic it is nominally an alternative to (SUPPORTED at corpus scale, OBSERVED for the visible sample) — there is no independent ground-truth source anywhere in the traced pipeline (DISPROVEN as a claim: no such source exists). A second, architecturally real but empirically negligible pathway exists where the classifier could train on its own prior predictions once a class is trust-floor-cleared (VERIFIED as a mechanism via constructed adversarial input; observed on at most 1 of 205 real historical training examples currently on disk, unconfirmed even for that one). Mission 31's characterization of this mechanism as having "real, ground-truth labels" and being "L2/L3-shaped" is **overturned in part**: the mechanism clears **L2** (a real, demonstrated causal chain from experience to a changed routing decision) under constructed/adversarial conditions, but does **not** clear **L3** — the required independent, non-circular feedback signal (evidence-vocabulary.md, causal-chain link 3) is absent. There is no evidence, and no instrumentation capable of producing evidence, that this mechanism improves task classification against any ground truth independent of itself.

## Question

Does `task_type_classifier.py` constitute a genuine causal learning mechanism (a mechanism whose adaptation is driven by a supervision signal independent of the static heuristic it coexists with, and which demonstrably improves routing against some criterion outside itself) — or is its apparent learning better explained as a statistical reproduction of the pre-existing keyword heuristic, a self-confirming/circular signal, or a real-but-empirically-inert capability?

## Hypotheses

H0 (no meaningful activity), H1 (genuine independent supervision), H2 (heuristic imitation), H3 (circular/self-confirming supervision), H4 (real adaptation, no demonstrated improvement), H5 (routing changes without downstream consequence), H6 (genuine useful learning) — see Mission 32's tasking for full definitions.

**Evidence favors H2 as the dominant, quantitatively confirmed explanation (99.5% of the real training corpus)**, with **H3 confirmed as a real architectural mechanism** but empirically negligible in the observable historical record, **H4 confirmed** (real adaptation demonstrated, improvement unmeasurable — no independent criterion exists), and **H1 and H6 disproven** at the "independent, non-circular, demonstrably improving" bar. **H0 is disproven** — the mechanism is not inert; it has a real, demonstrated effect on routing under the right conditions. **H5 is partially disproven** — routing changes do reach real downstream code branches (traced, not executed end-to-end).

## Scope / Non-Goals

This mission did **not**: mutate any production code or persisted state (no `.learn()`, `.save()`, or pickle write calls were made against the real classifier at any point); restart `run.py` or Ollama; measure whether the classifier's predictions are semantically "correct" against any external standard (none exists — see Ground-Truth Search below); fully execute an end-to-end live generation to observe Layer D/E behavioral consequences (deliberately out of scope to avoid unnecessary Ollama load and stay within a tight, bounded investigation — see Adversarial Findings); or audit `river_deliberation.py`'s or `self_edit_manager.py`'s own learning mechanisms beyond their role as downstream consumers of `task_type`.

The single most important structural fact this trace establishes, confirmed by direct source read (Evidence m32-001, m32-002): **the label used to train the classifier is not sourced independently of the routing decision it is meant to inform — it *is* the routing decision, fed back to the same mechanism that (sometimes) produced it.** Whether this constitutes heuristic-imitation (H2) or circular self-training (H3) depends entirely on which branch of `resolve_task_type()` produced that specific label, which the corpus scan below answers quantitatively.

## Adversarial Findings

**Self-confirming test caught in my own first attempt, corrected before being reported** (per this project's own standing discipline, CLAUDE.md's repeated "found and fixed my own measurement bug" pattern): the first probe (`scratchpad/mission32_probe.py`) compared `resolve_task_type()`'s live output against `detect_task_type()`'s keyword ladder as the "classifier-ablated" counterfactual, for prompts where `compute_intent_heatmap()`'s own confidence was already `>= 0.4`. In that regime, `resolve_task_type()` *never calls* `detect_task_type()` at all — the two functions being compared are **two independently-hand-coded keyword lists that disagree with each other**, not "classifier vs. no classifier." This produced 2 false "override" signals. Caught by checking the `fallback_triggered` (`heatmap[primary] < 0.4`) condition explicitly in a second probe and re-running; the corrected experiment (m32-004) only credits an override when the fallback branch was actually reached. **Left in the record as evidence the corrected version's methodology, not smoothed over.**

**Static heuristic dressed as learning, tested directly, not just asserted**: the two genuine overrides observed in `mission32_probe2.py` were both triggered by the word "poem," which is *already a literal entry in `compute_intent_heatmap()`'s own `creative_keywords` list*. The NaiveBayes model's high confidence (0.944–0.975) is consistent with it having learned a strong word→class association for exactly the surface lexical cue the static heuristic already encodes — differing arithmetic (learned log-odds vs. hand-tuned additive scoring) producing a different threshold crossing on the *same* underlying signal, not evidence of a differently-sourced signal. This is the simplest explanation that accounts for the override without invoking independent learning, and it was tested (word-level inspection of the triggering vocabulary against the heuristic's own keyword lists), not merely asserted.

**Evaluator leakage / circularity, quantified rather than left as a theoretical concern**: the corpus-wide scan (m32-005) is the decisive test here. If the classifier's training labels were independent of the static heuristic, there would be no reason for 99.5% of them to be exactly reproducible by re-running `compute_intent_heatmap()` alone on the same text. The near-total overlap is strong, quantitative evidence against H1 and for H2 as the dominant real mechanism.

**Instrumentation-changing-the-behavior check**: the ablation experiments toggle a module-level flag (`TASK_TYPE_CLASSIFIER_AVAILABLE`) for the duration of one function call, in a throwaway subprocess reading the pkl read-only — this cannot have affected the real running server or the persisted file, and was verified never to call `.learn()`/`.save()` (confirmed by re-reading `predict()`'s source before running anything against the real state: it calls only `predict_proba_one`, never `learn_one`).

**Randomness check**: NaiveBayes's `predict_proba_one` is deterministic given fixed model state and input text (no sampling involved) — re-running the same prompt against the same loaded model would reproduce the identical confidence value, so the override results are not attributable to stochastic noise. Not independently re-run to confirm determinism in this pass (judged unnecessary given river's NB implementation is a closed-form probability computation, not a sampling procedure) — **flagged as an assumption (INFERRED), not independently VERIFIED**, per this project's own discipline against silent hedging.

**Selection-without-learning check**: ruled out — `observation_counts` and the underlying NB weights genuinely change with each real `learn()` call (confirmed via source: `learn_one()` is a real online update, not a cache write), and the trust-floor gate genuinely activates/deactivates classifier participation based on accumulated count, which is itself real accumulated state, not a fixed selection among pre-existing options.

**Stale documentation check**: Mission 31's own report (line 90) explicitly names the live risk this mission was built to test ("the one real risk here is selection without learning masquerading as learning if the classifier's predictions rarely actually override the keyword ladder in practice") but states plainly that it did not test it, noting only that "real persisted confidence isn't independently re-verified per-call in this mission" while "the trust-floor arithmetic (3 of 5 classes past floor) is real, current, ground-truth data" [paraphrase corrected post-independent-review: the original draft of this sentence attributed a fabricated verbatim quote, "not confirmed as of this writing," to line 90 — that exact phrase does not appear anywhere in Mission 31's document; the underlying point (Mission 31 flagged this risk and did not test it) is accurate and unaffected]. This mission closes that gap — see Reconciliation below.

## What Is Actually Proven

- The classifier trains, persists, and is read back (VERIFIED, direct state read).
- The classifier's real, current, unmutated state can and does change `resolve_task_type()`'s routing output relative to a disabled counterfactual, under constructed conditions that reach the `<0.4` fallback branch (VERIFIED, controlled experiment against real state).
- For 99.5% of the real, currently-available training corpus, the label the classifier trained on is mechanically, deterministically reproducible by the static keyword heuristic alone — meaning independent supervision (H1) is disproven as the dominant explanation, and heuristic imitation (H2) is the best-supported account of what this mechanism has actually learned.
- No independent ground-truth criterion for `task_type` correctness exists anywhere in this codebase.

## What Is Only Supported

- That the classifier's downstream consumers (token budget, `DIRECT_ECHO_TASKS`, RiverBrain bucketing, self-edit target selection) actually produce a different real response or outcome when routing differs — traced via source, not executed.
- That the 99.5% heuristic-derived figure holds across the classifier's complete 480-observation training history, not just the 205-example visible remainder.

## What Remains Unknown

- Whether the classifier's predictions, on the rare occasions they do override the heuristic, are more or less *correct* than the heuristic's own decision — unanswerable with current instrumentation, since no independent ground truth exists.
- Whether the 1 real historical example with heatmap confidence < 0.4 actually was routed through the classifier at the time it was logged (2026-08-31) — would require reconstructing the classifier's exact trust-floor/confidence state at that historical moment, not attempted this pass.
- What fraction of *all* real conversational traffic (not just the training-eligible subset) reaches the `<0.4` fallback branch — the 205-example sample is a reasonable proxy but was not independently cross-checked against the full, untrustworthy-filtered traffic volume.

## What Was Disproven

**Mission 31's claim, preserved verbatim**: *"`task_type_classifier.py`, a genuine supervised online learner with real ground-truth labels"* (line 10) and, in its evidence table, *"The prompt's own real, ground-truth `task_type` label"* (line 34) as the source of the classifier's training signal.

**This mission's finding**: the label is not ground truth independent of the mechanism being evaluated — it is, for 99.5% of the real, currently-available training corpus, the output of the exact static keyword heuristic (`compute_intent_heatmap()`) that the classifier exists as an alternative to, fed back to the classifier as if it were external supervision. Mission 31's own line 90 explicitly flagged this as an untested risk ("real persisted confidence isn't independently re-verified per-call in this mission") rather than a settled finding — this mission closes that gap, and the closure does not support Mission 31's "ground-truth label" framing. **Mission 31's characterization of this mechanism as "L2/L3-shaped" is downgraded to L2, explicitly not L3**, on the specific grounds that L3 requires the independent-signal property this mission disproves.

No claim from CLAUDE.md itself was contradicted — CLAUDE.md's own description of this module ("online BagOfWords+MultinomialNB secondary signal... trust-gated per class and trained only on `is_trustworthy_training_example()`-filtered examples") is accurate and consistent with everything found here; it makes no "ground-truth" or "genuine learning" claim that this mission's findings would overturn.

## Recommendations

1. **The decisive next experiment, if this mechanism's classification matters going forward**: instrument `resolve_task_type()` (or `detect_task_type()`) with a real-time counter of how often the `<0.4` fallback branch is reached across *all* real conversational traffic (not just the training-eligible subset), and separately, how often the classifier's prediction actually differs from what `detect_task_type()`'s own keyword ladder would have said in that branch. This would upgrade the "materially rare" SUPPORTED claim above to a VERIFIED, precisely-quantified one.
2. If independent supervision is ever wanted for this mechanism, the missing piece is a genuine external label source — a small human-annotated fixture set, or a council/LLM-judge label computed independently of both `compute_intent_heatmap()` and the classifier's own prior predictions — not currently present anywhere in this codebase.
3. `liveness_ledger.py`'s `task_type_classifier` check (Evidence m32-008) validates input filtering only; it would not detect a future regression toward *more* circularity (e.g., a code change that lowers the 0.4 threshold, increasing how often the classifier trains on its own predictions). A new check specifically measuring the heuristic-agreement rate on trustworthy training examples (mirroring this mission's corpus scan) would close that gap — not built in this pass, per the investigation-only scope.
