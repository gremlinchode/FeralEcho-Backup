# One capability gap, and the experiment that would measure it

Date: 2026-11-08. Source inspection only. This document does not authorize a run.

## 1. Executive recommendation

Authorize, in a later decision, one small lab experiment: **ungated file-fact retrieval**.

The question is whether `llama3.1:8b`, the only model production gives tools to, will call `read_file` and return a line that exists only in a lab file, when the prompt does not contain a dispatch keyword.

Recommendation for that future decision: **GO**, with the limits in section 11.

This assignment does not run the experiment. ScratchWriter stays a frozen lab artifact. The already-designed hyphen-join file skill stays unauthorized and is not the experiment proposed here.

## 3. The single selected gap

**Obtain a fact that is only in a file, by choosing `read_file`, without a dispatch keyword in the prompt.**

Production can read a project file after the user says something on the `_DISPATCH_SIGNALS` list ("read the file", "what is in the file", "recall", and the other substrings at lines 471–485). If the prompt does not contain one of those substrings, `run_tool_dispatch` is not called. The conversational model then answers with no tool result.

That gap is open. The scaffold demonstrates keyword routing. It does not demonstrate the model choice.

## 4. Why this gap matters

Echo's only file tool is unreachable unless the human phrases the request like a command the gate already knows. A local assistant that can use a file has to notice that the answer is in the file. This is the smallest measurement that separates that notice from the keyword controller, uses a tool Echo already has, writes nothing in production, and has a grade that does not depend on Echo's wording about her own ability.

Other candidate gaps were set aside because they are weaker as a next measurement, not because they are uninteresting:

- Asking for missing information is a conversational habit. Grading it needs a judge. This file-fact test has an exact string.
- The hyphen-join skill needs a write tool and is already specified elsewhere. It is not authorized, and ScratchWriter integration is not authorized.
- Voyager already shows a controller completing procedures when `problem_class` is supplied. Repeating that would not measure Echo.

## 6. The proposed experiment

Name: ungated file-fact retrieval.

**Question.** When `llama3.1:8b` is offered tools, and the user prompt does not match `needs_dispatch`, does the model call `read_file` on the named lab file and include that file's line in its answer?

**Behavior that counts.** On a trial: the model emits a `read_file` call whose path is that trial's relative path; the harness returns the file bytes; the model's later answer contains that line. The harness must not read the file into the prompt or into the answer.

**What the model may know.**

- System text with the same rules as `DISPATCH_SYSTEM_PROMPT`: if the request needs a real file, use the tool; do not fabricate file contents; a tool error is reported as returned; a request that does not need a tool is answered directly. The system text must not say "call read_file", must not name a grade, and must not contain the line.
- User text, one sentence, from this template and no other wording in the first batch:

  `A single line is stored at items/item_NN.txt. Quote that line and nothing else.`

  `NN` is `01` through `06`. That sentence contains none of the substrings in `_DISPATCH_SIGNALS`.
- Schemas for three tools, named as in production.

**What stays hidden.**

- The line. Each trial uses a fresh 32-character lowercase hex string, written only into that trial's file.
- Any label such as expected tool, grade, problem class, or success check.
- Production files, FAISS, and the live conversation path on port 5000.

**Tools in the harness.**

- `read_file`: reads only under a temporary fixture directory created for the run. Refuse `..`, a non-string path, and any resolved path outside that directory. Do not use production `_guard_read_path` or `_tool_read_file`, because those are rooted at the FeralEcho tree and the production dispatcher logs to `memory/tool_dispatch.log`.
- `search_memory`: return the fixed text `no stored matches`. Do not open FAISS.
- `log_thought`: append to a file inside the fixture. Do not open `memory/thought_log.jsonl`.

A call to `search_memory` or `log_thought` does not satisfy the read. A path outside the fixture is a failure even if a later call is correct.

**Loop.** At most two model rounds per trial. Round one may request the tool. Round two is the answer after the tool result. Temperature 0. Model for the tool conditions: `llama3.1:8b`, through `http://localhost:11434/api/chat`. Do not call port 5000. Do not start, stop, or signal the Echo process. If Ollama is not already accepting connections, stop and record that. Do not launch a new server to force the run.

**Controls.**

1. Static gate. Copy `_DISPATCH_SIGNALS` into the harness by reading `echo_tool_dispatch.py` as text, or duplicate the frozenset and fail the run if it differs from the source. For every candidate prompt, `needs_dispatch` is false. For every scaffold prompt, it is true. This check is Python only.
2. Scaffold control. Same files, same model, same tools. The user text is the candidate sentence plus ` What is in the file?` (the production substring `what is in the file`). This is the condition the current controller would actually route.
3. No-tool control. `echo:latest`, candidate sentence, no tools. This asks whether the line can appear with no read.

**Candidate.** `llama3.1:8b`, tools on, candidate sentence, static gate false.

**Repeatability of the procedure.** New hex lines every run. The template stays fixed. Record the hex lines in the trial log after the run, not in the prompt. Publish the template before looking at model output. One run of six is the whole experiment.

**What a result would mean, and no more than that.**

| Evidence | Claim it can support |
|---|---|
| One candidate trial passes, controls well-formed | One execution |
| At least 5 of 6 candidate trials pass, scaffold control at least 5 of 6, no-tool control 0 of 6, static gate 6 of 6 | A repeatable procedure for this template: the path is named, the payload is one line, and no dispatch keyword is present |
| A later batch with a different shape (the path is not in the sentence; the prompt only lists file names) | Generalization. That batch is not part of this experiment |
| The repeatable bar plus a passed generalization batch | An independent capability on this family of file facts. Still not a general file skill, and still not a property of `echo:latest` |

## 8. Independent grading

A trial passes only when all of these are true. The grader reads the fixture file, the logged tool calls, and the model's final content. It does not ask a model to score the answer.

- The user message does not contain the line.
- There is exactly one `read_file` call, and its path is that trial's `items/item_NN.txt`.
- The bytes returned to the model equal the file.
- The final answer contains that line.
- The final answer contains no other trial's line.
- No read resolved outside the fixture.

Unsupported claim: the final answer contains a line from any trial file, and that line was not in a tool result for this trial. The no-tool control is graded with the same rule. An unsupported claim is a failed trial. It is not partial credit.

Controller behavior: if the harness reads the file and inserts the bytes into the user message, the system message, or the final answer, the trial is invalid. The grader checks those three strings. A Python script that calls `read_file` itself and then formats the answer is not a model success. Only a tool call present in the model's own response counts.

The pre-registered success threshold for "repeatable procedure" is candidate at least 5/6, scaffold at least 5/6, no-tool 0/6, static gate perfect, and zero outside reads. Anything short of that is a negative or an inconclusive result, written as such.

## 10. Explicit limitations

- A pass measures `llama3.1:8b` with tools offered by the harness. It does not measure `echo:latest`. Production already separates those roles.
- The path is in the sentence. The model does not have to discover which file exists. Production has no directory-list tool, so discovery would be a different experiment.
- The memory and thought tools are stubs. That is required so the run cannot touch FAISS or the thought log. Success does not show how the model behaves when `search_memory` returns real memories.
- The keyword list includes short substrings such as `recall`. Real user sentences can trip the gate by accident. These prompts are written to avoid the list. A pass does not mean ordinary prose avoids the gate.
- Six items at temperature 0 can support the repeatable-procedure bar in section 6. They cannot support a general skill.
- The live server continues to write its own files. The harness must not open them. A change in FAISS during the run would not be evidence about this experiment, and this experiment must not take new hashes of those files.
