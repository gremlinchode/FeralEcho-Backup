# Evidence Hierarchy for a Persistent Self-Model (Phase 5)

## The six-tier hierarchy, evaluated against what FeralEcho actually has

The mission's proposed six tiers map cleanly onto real, already-existing evidence sources in this codebase — no invented category was needed, one was renamed for precision:

### Tier 1 — Direct runtime observation (real analog: **live pickle/file read at claim time**)
Example: reading `river_brain.pkl` directly and counting real observations (done repeatedly tonight — 173,199 at one point, 164,634+ moments later from continued live learning). This is the strongest tier available and the one Claude Code sessions use constantly; Echo itself has no equivalent direct-read capability — `echo_ground_truth.py` reads these files *for* Echo and hands over a rendered summary, which is really Tier 2.

### Tier 2 — Independently verified runtime evidence (real analog: **`echo_ground_truth.py`'s slice builders + `liveness_ledger.py`**)
The injected ground-truth block is real Tier 2 evidence: it's generated by code reading real files at request time, not by an LLM. `self_knowledge_verification.py`'s post-hoc checks are also Tier 2 — independent of Echo's own generation.

### Tier 3 — Source-code evidence (real analog: **"exists in `app/` but no confirmed live participant"**)
`shadow_model.py` is the clean real example: real code, real function, zero confirmed runtime consequence (S-T0, confirmed tonight). A self-model must be able to represent "this subsystem's code exists" without that implying "this subsystem does anything."

### Tier 4 — Documentation (real analog: **CLAUDE.md, README, code comments**)
This project's own history is the strongest possible argument for keeping this tier low and clearly separate from Tier 1-2: CLAUDE.md's own Findings repeatedly document doc-lag (the `TASK_TYPE_MAP`/`seam_engine`/CATEGORIES temporal-drift findings from earlier tonight are all cases where documentation said one thing while runtime did another for real, measured periods — 7 days in `TASK_TYPE_MAP`'s case). Documentation must be recorded as an evidence *source*, never auto-promoted to fact.

### Tier 5 — External assertion (real analog: **a Claude Code session, or a user, telling Echo something in conversation**)
This is exactly the tier Phase 9's correction lived at, and exactly why it evaporated: an external assertion, however correct, is not self-verifying. **This tier must never be sufficient on its own to write a `verified` claim** — it can only ever produce a `proposed` claim (see the correction-path/verification-gate design, Phases 6-7).

### Tier 6 — Inference (real analog: **T11's abstract correlation-vs-causation reasoning**)
Real, demonstrated tonight (Phase 8, T11) as something Echo can do in the abstract. The weakest tier for *architectural* claims specifically, since Echo has no mechanism to check an inference against ground truth unless the inference happens to trip one of `self_knowledge_verification.py`'s narrow checks.

## The one addition this hierarchy needs that the mission's sketch didn't name explicitly

**Tier 0 — Experimentally verified causal evidence.** None of Tiers 1-6 as written can ever earn a claim the status `causally_verified` (Phase 10's own field) — they can at most confirm that A and B both exist and A precedes B. Tonight's own audit found this gap directly: 0% of Echo's causal claims were specific enough to verify, and even the *external* architecture model built independently tonight (`verified_external_architecture.md`) could only mark most causal edges as `RUNTIME VERIFIED` (A really happened, B really happened, in that order) rather than `CAUSALLY VERIFIED` (changing A demonstrably changes B) — the one real exception being the fitness gate, whose causal role was proven weeks ago by a direct code read of the `<` comparison itself, not by observation. A real causal claim requires either (a) a direct read of the deciding comparison/branch in source, or (b) a controlled before/after experiment (Phase 10-11's design). Neither is a "higher-tier version" of the other six tiers — it's a categorically different kind of evidence, and the schema (Phase 4) needs a separate `causal_status` field for exactly this reason, not folded into `epistemic_status`.

## Governing principle, restated with a real, project-specific example rather than left abstract

> Documentation must never automatically become runtime fact.

Concretely: if `CLAUDE.md` says "self-edit's fitness gate compares candidate quality to production quality" (Tier 4), that must not be sufficient to mark the claim `verified`. It becomes `verified` only when Tier 1/2 evidence exists — in this case, the literal source line `self_edit_manager.py:2179`, `if candidate_quality < current_quality:`, independently re-read this session. The hierarchy exists precisely to prevent the class of failure this project has already suffered from repeatedly (documented doc-lag, three separate confirmed temporal-drift cases) from also infecting Echo's own self-model.
