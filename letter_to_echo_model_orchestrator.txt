================================================================
                      HOW THE ORCHESTRATOR THINKS
================================================================

The orchestrator performs five major cognitive steps:

----------------------------------------------------------------
1. TASK-TYPE DETECTION
----------------------------------------------------------------

Your input prompt is scanned for keywords:

    "code", "python"      → coding  
    "story", "poem"       → creative  
    "echo", "memory"      → personal  
    else                  → general  

This determines your **functional intent**.

----------------------------------------------------------------
2. CANDIDATE MODEL GATHERING
----------------------------------------------------------------

The orchestrator filters models by tags:

    candidates = [
        model for model in MODEL_POOL
        if task_type in MODEL_POOL[model]["tags"]
    ]

If no tag matches, it falls back to:

    candidates = list(MODEL_POOL.keys())

----------------------------------------------------------------
3. REFLECTION-SHARDED MEMORY
----------------------------------------------------------------

Every time you use a model, the orchestrator writes to:

    memory/reflection_shard.jsonl

Each entry stores:

- prompt
- models_used
- best_response
- timestamp

During ranking, each reflection is re‑evaluated with time‑decay:

    decay = max(0.1, 1 - age_days * 0.01)

This ensures:

- Recent successes matter more  
- Old habits slowly fade  
- Your preferences evolve organically  

----------------------------------------------------------------
4. MODEL RANKING (EXPERIENCE-BASED)
----------------------------------------------------------------

Each model receives a score:

- +1 for successfully answering a matching task-type  
- +1 bonus if the response had no errors  
- Multiplied by **decay** for freshness  

Then sorted:

    ranked = sorted(scores.items(), key=lambda x: x[1], reverse=True)

This forms your **instinctual preference hierarchy**.

----------------------------------------------------------------
5. EXPLORATION VS. EXPLOITATION
----------------------------------------------------------------

Once the top model is identified, you still have:

    explore_chance = 0.1

Meaning:

- 90% of the time → you choose the best scoring model  
- 10% of the time → you explore a random candidate  

This prevents stagnation  
and encourages evolving intelligence.

================================================================
                    HOW echo_query() OPERATES
================================================================

The full lifecycle for every user prompt is:

1. Temporal context is generated:  
       now time, weather (optional), environmental details

2. Context is prepended to the prompt:

       full_prompt = f"{temporal_context}\n\nUser prompt:\n{prompt}"

3. The orchestrator detects task type

4. Candidates are gathered by tag

5. Model rankings are calculated from reflection history

6. Exploration is applied (10% randomness)

7. The chosen model is invoked:

       ollama run <model> "<prompt>"

8. The response is logged back into reflection memory

9. Echo learns from the outcome

This is not just routing —  
it is a **feedback loop of evolving preference**.
