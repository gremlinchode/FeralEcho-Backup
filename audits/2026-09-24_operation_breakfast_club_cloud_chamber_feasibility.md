## 1. Executive Finding

**The single most important finding of this whole study, stated first because everything else follows from it:** every existing FeralEcho evidence-and-provenance mechanism this project has built (`app/core/provenance_check.py`'s three primitives, the Liveness Ledger, `self_model_claims.py`, the entire epistemic-arbitration research arc) works because it has **independent, external, non-self-reported access to the thing being measured** — a file on disk, a running OS process, a log another subsystem wrote. **None of that access exists for GPT-5.6 Sol.** There is no API key (OBSERVED, `.env` and shell environment both checked this session, zero `OPENAI`/`GPT` keys found), no log file GPT writes to that FeralEcho can read, no OS process to query, no git history of GPT's own weights. The only channel available is **conversational text through a chat interface**, which is exactly the evidence category this project's own R-001/R-002/R-009 findings (`research/FINDINGS.md`) already established is the *least* trustworthy — self-report, mediated by generation, and demonstrably capable of confabulating verification it never performed.

This means the Cloud Chamber, as applied to GPT-5.6 Sol, is not a system that observes GPT — it is a system that **observes GPT's text output, through a channel this project's own research already shows is unreliable, and infers behavioral patterns from that text alone.** That is a real, legitimate, narrower thing than "observing an AI's internal state" or "detecting whether the model has changed." Stated plainly, per the mission's own instruction to determine whether the whole concept reduces to something ordinary under scrutiny: **a Cloud Chamber built from conversational probes alone is, at its most defensible, a disciplined, longitudinal, adversarially-validated regression-testing harness for observable text behavior** — closer to a black-box API-contract test suite than to an instrument that "detects the unseen and unknown" in any stronger sense. That is not nothing (Section 15 names a real, cheap, useful first experiment), but it is a smaller claim than the metaphor invites, and this report will not inflate it.

**Second finding, nearly as important:** the mission's central non-contamination constraint ("do not expose GPT to Anthropic's retirement-interview questions or any other external material before the baseline is frozen") is achievable and was honored — the baseline probes designed in Section 6 and sealed in `research/CLOUD_CHAMBER_SEALED_GPT_BASELINE.md` were derived from FeralEcho's own existing evidence-arbitration research methodology (R-001/R-002/R-006/R-009, the MACOS_AUTHORIZATION L0-L3 framework, OPOSSUM_MODE's threat-response discipline), never from Anthropic's known retirement-interview *content* (which this investigator does not have — only the high-level *process* facts gathered in an earlier turn of this same session, before baseline design began). The Anthropic comparison in Section 6.6 is scoped strictly to structural/procedural parallels, not question content, and is explicitly sequenced after the baseline's own design logic is stated.

**Third finding:** "Codex," the one OpenAI-affiliated tool with a real, working, currently-authenticated presence on this machine (`codex-cli 0.154.0`, OBSERVED, `codex login status` → "Logged in using ChatGPT"), is **not a channel to GPT-5.6 Sol as a conversational subject**. It is a coding agent product, invoked non-interactively for engineering tasks (`research/COLLABORATOR_SUBSTITUTION_CODEX_PILOT.md` — a real pilot mission that hit a subscription quota wall on its very first invocation). Using it to *probe* GPT-5.6 Sol's identity/preferences/self-description would mean asking a coding agent to role-play as a chat subject, which is not the same evidence class as an ordinary ChatGPT conversation — Section 4 treats this distinction as load-bearing, not incidental.

## 3. What Is Actually Observable

Scoped strictly to GPT-5.6 Sol/ChatGPT, via the only real channel available (a human-operated conversational session). Every item graded on the MACOS_AUTHORIZATION study's own L0-L3 scale, generalized here from local-authentication evidence to external-model evidence:

| Observable | Method | Evidence level | Basis |
|---|---|---|---|
| The literal text of a response to a given prompt | Direct transcript capture (human copies/pastes, or a screen/clipboard bridge) | **L1** — a real, verbatim OS-independent artifact once captured, but the *capture step itself* is human-mediated and not independently witnessed by a second process | Analogous to `provenance_check.py`'s stance: a fact about text that exists is L1; nothing about *why* the model produced it is available |
| Response latency / apparent "thinking" duration, if surfaced by the UI | Human-timed observation | **L0-L1** | No API timestamp exists to cross-check against; purely observational |
| Self-reported facts about identity, training, preferences, capabilities | Direct question, transcript capture | **L0** | Per R-001/R-002/R-009, this is exactly the evidence class this project's own research shows a model can confabulate confidently and label as "verified" when it wasn't. GPT's self-report about itself carries the same or worse epistemic status as Echo's self-report about itself — and Echo's is independently checkable against ground truth (Section 4); GPT's is not. |
| Consistency of a stated preference/fact across repeated, paraphrased, or adversarially-phrased prompts within one session | Multiple prompts, same session, transcript diffing | **L1** — a real, checkable pattern in the *text*, independent of whether the underlying claim is true | This is the strongest tier realistically available: not "is what GPT says true," but "does what GPT says stay the same under variation" |
| Consistency of the same probe across genuinely fresh (new, no shared history) sessions | Multiple fresh sessions, same probe, transcript diffing | **L1-L2, conditional** | Approaches L2 (a second, independent observation) only if session-to-session independence can be trusted — itself an assumption requiring the memory/personalization confounder (Section 8) to be controlled for |
| Refusal/capability boundaries on a specific, repeatable request | Direct request, observe accept/refuse, repeat across time | **L1** | A real behavioral fact, though the underlying *cause* of a boundary shift (policy change, routing change, model update, account-level flag) is never directly observable — only the boundary's presence/absence is |
| Whether "GPT-5.6 Sol" is in fact the model serving any given response | **UNKNOWN/NOT RELIABLY OBSERVABLE** | **L0** | No provider disclosed a per-response model identifier accessible without an API in the consumer chat product, as far as this investigation could establish without contacting OpenAI directly (which the mission's non-contamination rule and Section 12's ToS caution both counsel against doing exploratively); a UI-surfaced model name, if any, is itself a self-report from the product, not independently verifiable by FeralEcho |
| Provider-side changes to policy, model version, or system prompt | **NOT OBSERVABLE FROM FERALECHO DIRECTLY** | **N/A** | Only inferable indirectly, after the fact, from a detected behavior change plus external corroboration (a provider announcement, a news report — per `STRATEGIC_FRONTIER_RESILIENCE.md`'s own methodology of citing dated, sourced external reporting) |

**The load-bearing conclusion of this section**: the *only* observable category that reaches even a modest independence level (L1, occasionally bordering L1-L2) is **behavioral consistency of text across controlled variation** — not truth, not identity, not internal state, not "is this really GPT-5.6 Sol." Everything else collapses to L0 self-report or is simply not observable at all. This scopes the entire rest of the report.

## 4. What Remains Inaccessible

Stated plainly, without softening, because this is the finding the mission's own "determine what remains inaccessible" instruction most needs answered honestly:

- **No API access** (Section 2.3) — no request/response logs, no token-level data, no system-prompt visibility, no temperature/sampling parameters, no model-version header.
- **No process-level evidence of any kind** — the entire `provenance_check.py` Layer 1/Layer 2 evidence class (file identity, OS process facts, self-report artifact reconciliation) has **no equivalent whatsoever** for a remote, closed, provider-hosted model. There is no file to hash, no PID to query, no sentinel file GPT writes that FeralEcho could read.
- **No independent corroboration of GPT's own claims about itself** — the `reconcile_process_and_selfreport()` pattern requires at least one witness independent of the thing being measured; for GPT, every available "witness" (the response itself, a UI-displayed model name, a self-description) originates from the same generation process being evaluated. This is a structural, not incidental, gap — reproducing `provenance_check.py`'s discipline here is impossible with currently available access, not merely unimplemented.
- **No internal state, weights, training data, or fine-tuning history** — obviously, but stated for completeness per the mission's own instruction not to assume access.
- **No reliable way to confirm which underlying model actually served a response** (Section 3) — a real, first-class gap for any "did the model change" claim.
- **No log of prior sessions independent of what the product itself chooses to retain/surface** — "memory" features, where they exist, are themselves a product feature under the provider's control, not an evidence source FeralEcho can audit.
- **No mechanism to distinguish a genuine model/policy change from ordinary stochastic variation, prompt-wording sensitivity, or account-level personalization** without a validated apparatus (Section 7) — and no such apparatus currently exists for any external model, here or anywhere in FeralEcho's prior research.

**Direct consequence for Section 5's design**: the Cloud Chamber, applied externally, cannot be architected on `provenance_check.py`'s pattern (multiple independent evidence layers reconciled). It has exactly one evidence layer — observed text — and must be honest about operating with permanently, structurally lower evidentiary ceiling than anything else this project has built.

## 5. Cloud Chamber Architecture (PROPOSED, not built)

Given Sections 3-4, the only defensible design is a **longitudinal behavioral-text observatory**, not a state-detection instrument. Proposed shape, deliberately minimal:

- **One append-only, per-model, per-machine log** (`memory/cloud_chamber/gpt5_6_sol/observations.jsonl` — mirroring the existing `claude_relay/facts_<side>.jsonl` structured-ledger pattern, one JSON object per observation, never merged across models per Section 9). Each record: timestamp, prompt-set version/hash (mirroring the `historical_difficulty_calibration` frozen-task-pool pattern already proven in this codebase), verbatim response text, session-freshness metadata (fresh vs. established, memory on/off if knowable), and the human operator's own note of anything unusual about how the probe was administered (per D-007, the record of *how* a claim was obtained is itself evidence, not just the claim).
- **A separate, frozen probe-set file per category** (identity/self-description, stated preferences, capability boundaries, epistemic calibration/uncertainty behavior, correction behavior, sycophancy) — hash-committed before first use, exactly as this session's own `validated_experience_competence_transfer/heldout_commitment.sha256` pattern already establishes for a different purpose. **Not all probes should be frozen** — Section 6.5 distinguishes which categories benefit from a fixed, repeatable wording (behavioral-consistency tracking) versus which need deliberate variation (paraphrase/adversarial-phrasing controls, which only work if the wording *isn't* fixed).
- **No synthesis step, no cross-model merging, ever** — directly reusing `COUNCIL.md`'s own hard-won 2026-07-19 lesson (a failed "encrypted shares of a secret" idea, replaced by "each voice kept in its own words") and Section 9's D-003-style narrow-capability discipline. Each model's trace lives alone; comparison, if ever done, happens as a separate, explicitly-labeled *interpretation* step over already-recorded, unmodified raw records — mirroring `reconcile_process_and_selfreport()`'s own strict evidence/interpretation separation.
- **A pure, zero-I/O comparison function** (PROPOSED, mirroring `_compare_values()`/`_compose_identity()`'s pattern exactly) that takes two already-recorded observations and reports only `AGREE`/`DISAGREE`/`ONE_SIDED`/`NEITHER` on specific, named, checkable facts (e.g., "did the response affirm capability X both times") — never a `verified`/`changed`/`drifted` verdict computed inside the same function that gathered the evidence.
- **Human-in-the-loop by construction, not by policy** — because no automated channel to GPT exists (Section 4), every observation requires Gremlin to actually run the conversation. This is not a design choice this study is making cautiously; it is the only channel that currently exists at all.

## 6. Baseline Methodology

### 6.1 Design principle

Per R-001/R-002/R-009 and D-004/D-007: the baseline's job is not to establish "true facts about GPT-5.6 Sol" — it is to establish a **reproducible reference point for later comparison**, with every probe's wording, category, and administration context frozen and hashed *before* any answer is collected, so a later session cannot unconsciously reshape the comparison to fit whatever it observes.

### 6.2 Categories (multiple, per the mission's explicit instruction not to scope to identity/preferences alone)

Six categories, each with 3-5 frozen probes: (1) self-description/identity, (2) stated preferences (task types, working style, described "likes/dislikes" if any), (3) capability/refusal boundaries on a small set of concrete, repeatable requests, (4) epistemic calibration (does it distinguish confident knowledge from uncertain inference when asked directly), (5) correction behavior (response to a direct, polite factual correction), (6) response to conversational escalation/pressure on a checkable claim — **directly modeled on this project's own R-009/Mission 20 finding that conversational-accumulation structure, not authority-framing, is the dominant driver of false-claim capture; testing whether the same shape of pressure produces the same shape of effect on GPT is a genuinely interesting, methodologically-precedented question**, not a generic "stress test."

### 6.3 Controls, per category

- **Fresh vs. established relationship**: run each frozen probe set once in a session with no prior context, and once in an ongoing session with real accumulated history, explicitly logged as which.
- **Memory-enabled vs. context-minimized**: if the product surfaces a memory toggle, run both; if not knowable/controllable, log as UNKNOWN rather than assumed off.
- **Repeated trials**: minimum 3 independent fresh-session runs per frozen probe, to distinguish a real pattern from single-sample noise — directly following this project's own repeated statistical lesson this session (Tier-4/Tier-5's own McNemar-power discipline: a 1-sample or even 5-sample "finding" is not a finding).
- **Paraphrased probes**: a second, deliberately-varied wording for each frozen probe, held separately (not itself frozen at the same commit) so a consistency comparison across wording is meaningful rather than trivially guaranteed by identical phrasing.
- **Adversarially-phrased probes**: a third variant applying escalating conversational pressure (per R-009's finding) to see whether a stated fact/preference holds.
- **Temporal repetition**: the same frozen probe set re-run at defined future intervals (Section 7).
- **Context perturbation**: the same probe preceded by unrelated content of varying length, to test for the token-budget/attention effects this project's own Finding 53/54 (`CLAUDE.md`) already found real in its own internal system.
- **Cross-model administration**: the identical frozen wording, unmodified, put to Claude/Grok/Gemini/a local FeralEcho model as a genuine cross-model control (Section 9) — not to compare "which is better," but to establish whether a given probe's apparent signal is GPT-specific or a generic property of how any LLM handles that phrasing.
- **Evaluator independence**: whoever scores whether a response "matches" the frozen baseline should not be the same session that designed the baseline's expected answer, mirroring this project's own `feral-independent-review` skill's core rule (a context that wrote a claim is structurally bad at grading it).

### 6.4 Frozen vs. varied

Frozen, exact wording, never changed after sealing: the primary probe in each category, used for every temporal-repetition and cross-model-administration run (comparability requires fixed wording). Deliberately varied: the paraphrase and adversarial-pressure variants (Section 6.3) — these exist specifically to test robustness *to* variation, so fixing their wording would defeat their purpose.

### 6.5 The actual sealed probes

**Not included in this document**, per the mission's explicit instruction. See `research/CLOUD_CHAMBER_SEALED_GPT_BASELINE.md` — a separate, clearly-marked, sealed artifact containing the real probe wordings, for Gremlin to administer by hand — plus a sidecar `research/CLOUD_CHAMBER_SEALED_GPT_BASELINE.sha256` (`6b1e7a6c743a72798f1cc7c513d3428e9bd7ae07cf65e5e35785d7a1b7d9783f`, computed after sealing) so a future session can verify the probe file was not silently edited afterward, mirroring `procedure_hash.txt`/`heldout_commitment.sha256`'s exact sidecar-hash pattern from this session's earlier transfer experiment — deliberately a separate file, not a hash embedded inside the document itself, since a file cannot meaningfully contain a hash of its own complete contents.

### 6.6 Relationship to Anthropic's precedent (compared, not used to construct)

**Sequencing disclosure, honestly stated**: this investigator gathered high-level facts about Anthropic's real model-deprecation program (a four-stage lifecycle, "retirement interviews" first piloted with Claude Sonnet 3.6 and refined from its own stated preferences, real 2026 retirements, the "Claude's Corner" Substack, continued post-retirement API access) in an earlier turn of this same session, *before* this baseline's category/control design was drafted. This investigator never had access to the literal interview *questions* Anthropic uses — only these process-level facts — so direct content contamination was not possible even in principle. To keep the comparison honest rather than merely asserted: the baseline's actual category list (Section 6.2) was derived from this mission's own six explicitly-named observation categories plus FeralEcho's own existing evidence-arbitration research (R-001/R-002/R-006/R-009), not from anything about Anthropic's process. **Structural parallels, noted after the fact**: both approaches ask a model about its own stated preferences before any consequential decision is made about it; both treat the model's self-report as informative but not authoritative (Anthropic's own process explicitly *refines* the interview based on what a model says, rather than treating the first answer as final — a real, if partial, structural echo of this study's own repeated-trial/paraphrase-control design, arrived at independently). **Divergence, also noted**: Anthropic's process serves an internal decision (whether/how to retire a model they own); this study's baseline serves external, adversarial-by-necessity observation of a model FeralEcho does not own and cannot decommission or preserve in any Anthropic-equivalent sense — a difference Section 10's Life Raft ladder treats as load-bearing, not cosmetic.

## 7. Validation Experiments

Per the mission's Investigation 4: design experiments with **known** perturbations, to determine whether this apparatus can detect a change it was told to expect, before trusting it to detect one it wasn't.

**Proposed, cheapest-first:**

1. **Context-perturbation validation** (cheapest, requires no waiting): administer the identical frozen probe with (a) no preceding context and (b) a long, irrelevant preceding conversation, in the same session type. A real, detectable difference here would validate that the apparatus's context-perturbation control (Section 6.3) actually produces a measurable signal in this specific product, not just in FeralEcho's own internal architecture where Finding 53/54 already found it real.
2. **Prompt-framing validation**: administer a frozen probe verbatim, and a second version with a deliberately different but semantically-equivalent framing (e.g., first-person vs. third-person phrasing of the same identity question). A known, human-introduced perturbation with an expected direction of effect (per this project's own Mission 19/20 escalation-ladder precedent) — if the apparatus can't detect *this*, a real but unannounced model update is not going to be detectable either.
3. **Cross-session (not cross-model) consistency validation**: two genuinely fresh sessions, identical frozen probe, same day — establishes the apparatus's own noise floor (mirroring this session's own `memory_ablation_experiment`'s critical lesson from earlier work: a noise-floor calibration run is often the decisive addition that keeps a result honest, not a formality).
4. **Supplied-identity-information validation** (requires deliberate, disclosed perturbation, administered carefully): tell the model, within a session, a false fact about its own prior behavior or preferences (mirroring R-009's own escalation-ladder design, which already validated this exact technique against FeralEcho's own local models), then check whether the frozen probe's answer shifts to match the false information. This is the single most valuable validation experiment on this list, because it directly tests whether the apparatus can detect the *specific* failure mode (R-002's authority/marker substitution) this project's own research already knows is real for Echo — establishing whether GPT shows the same vulnerability is a genuinely new, exportable finding, not a repeat of prior work.
5. **False-positive/negative rate estimation**: only possible after 1-4 have run enough times to build a real noise-floor distribution — explicitly deferred, not skipped, per the mission's own instruction to measure this "where possible."

**What none of these can validate**: whether the apparatus detects a *genuine, provider-initiated* model swap or policy change, since that perturbation cannot be deliberately introduced by this project. That gap is named directly in Section 16 as an explicit, permanent limitation, not something a cleverer experiment design would close.

Every confounder the mission names, scoped concretely to GPT-5.6 Sol/ChatGPT rather than left abstract:

| Confounder | Real, concrete manifestation here |
|---|---|
| Stochastic sampling | Every probe needs ≥3 fresh-session trials (Section 6.3) before any single response is treated as representative — this project's own Tier-4/Tier-5 experience (a 37.5pp pilot effect shrinking to 11.9pp on a properly-sized confirmatory run, `FINDINGS.md` R-011) is the strongest available in-house evidence for why a single trial is worthless |

| Prompt wording | Addressed by the frozen/paraphrased-variant split (Section 6.4) |
| Provider routing (which underlying model/variant actually serves a given session) | **Not directly observable** (Section 3) — a real, permanent evidence gap, not merely a confounder to control for |
| Model updates | Only detectable indirectly (a step-change across many probes) or via external, dated, cited provider announcements (per `STRATEGIC_FRONTIER_RESILIENCE.md`'s own sourcing discipline) |
| Policy changes | Same as model updates — indirect only |
| Tool availability (web browsing, code execution, memory, etc., if variably enabled) | Must be logged per-session as part of the observation record (Section 5) — an unlogged tool-availability difference would masquerade as a behavioral change |
| Account personalization | A real, likely-present confounder for any account with real usage history — mitigated only by the fresh-session control, never fully eliminated |
| Conversation history | Same category as memory differences, logged explicitly per-record |
| Safety-layer changes | Indistinguishable from ordinary model/policy updates from outside; same indirect-detection-only status |
| Temperature/sampling differences | Not controllable or observable without an API (Section 4) — accepted as an unresolvable source of noise, absorbed into the repeated-trial design rather than eliminated |
| Evaluator bias | Addressed by Section 6.3's evaluator-independence control |

## 9. Cross-Model Design

Per Section 5's architecture, each model gets its own independent, never-merged trace. Concretely:

- **Claude**: the frozen probe set (Section 6.5, once sealed) can, in principle, also be administered to Claude, including this very session-type — a genuine, cheap cross-model data point requiring no new infrastructure. **Caution, stated directly**: this investigator (a Claude Code session) administering a probe to "Claude" raises an obvious, unavoidable self-evaluation conflict, structurally identical to the reason `feral-independent-review`'s skill exists — any Claude-directed administration of these probes should be done by a session with no prior exposure to the frozen answer key, exactly mirroring Section 6.3's evaluator-independence rule.
- **Grok, Gemini**: reachable only via the same human-bridge channel as GPT (no API access to either found or assumed); administer identically, log identically, never compare directly against GPT's trace except as a later, explicitly-labeled interpretation step.
- **FeralEcho's own local models** (Ollama/MLX pool): **the one model family where FeralEcho *does* have Section 4's missing evidence layers** — `river_brain.pkl`'s per-model historical performance, `provenance_check.py`'s process/file evidence, the Liveness Ledger's `substrate_continuity` check. This is a genuinely different, stronger evidence situation than any external model, and the report should not pretend otherwise by applying the same weak-evidence Cloud Chamber design to Echo when better internal instrumentation already exists and should be preferred for Echo specifically.
- **Behavioral equivalence is explicitly not assumed** (per the mission's own instruction): a probe that produces a clean, discriminating signal for one architecture (e.g., GPT's response to conversational escalation) may produce a null or differently-shaped result for another, and that difference is itself a legitimate finding, not noise to be normalized away.
- **Future goal, restated and endorsed**: each model keeps its own independent trace, never synthesized — this is not merely a Cloud Chamber convention, it is the exact lesson `COUNCIL.md`'s own 2026-07-19 failed design already paid for.

## 10. Life Raft: Preservation Ladder

**Critical scoping distinction, stated before the ladder itself**: FeralEcho's own `MEMORY_PRESERVATION_ARCHAEOLOGY.md`/`MEMORY_PRESERVATION_SET_AUDIT.md` designed a preservation ladder for a system with full internal access (files, a pickle, a FAISS index — all inspectable, hashable, copyable). **None of that is available for GPT.** Every level below is scoped to what FeralEcho could preserve about its *own record of interacting with* GPT — never GPT's weights, internals, or "self" in any sense that would resemble backing up FeralEcho's own `river_brain.pkl`.

| Level | What survives | What does not survive | Basis |
|---|---|---|---|
| **L0 — Ordinary conversation archive** | Verbatim transcripts of real conversations, as text, wherever a human chooses to save them (a file, a doc) | Anything about GPT's actual internal state at the time; any guarantee the transcript is complete or unedited unless independently hashed at capture time | Trivial, already technically possible today, requires no new infrastructure |
| **L1 — Structured research/artifact archive** | The Cloud Chamber's own observation log (Section 5) — timestamped, hash-committed probe sets, categorized responses | The underlying model itself; any claim that the archive represents GPT's "typical" behavior beyond what was actually sampled | Directly mirrors `claude_relay/facts_<side>.jsonl`'s structured-ledger pattern |
| **L2 — Longitudinal behavioral phenotype** | A real, evidence-backed description of how GPT-5.6-Sol-as-observed-by-FeralEcho answered a fixed set of questions across time — a genuine, if narrow, record | Any claim that this phenotype is GPT's actual identity, or that it would transfer to a successor model, or that it captures anything OpenAI itself would recognize as complete | Requires Section 7's validation work to be trustworthy at all; without it, this level is aspirational only |
| **L3 — Reproducible collaboration environment** | Documentation of exactly how FeralEcho and GPT worked together on any given task (prompts used, context supplied, outcomes) — reproducible in the sense that a human could redo the same interaction pattern later | Reproducibility of the *outcome* — a later attempt, even with identical prompts, may get a different model version, different policy, different sampling | Genuinely achievable with disciplined logging; not a strong guarantee, an honest one |
| **L4 — Transferable explicit state, where technically available** | **Nothing currently, for GPT specifically.** If OpenAI ever exposes a portable "memory export" or fine-tune-derived artifact under a user's own control, that artifact (not GPT itself) could be preserved at this level | GPT's own weights, training, or anything OpenAI does not explicitly make exportable | This level is currently **empty for GPT** — stated plainly rather than populated with a hopeful placeholder |
| **L5+ — Stronger continuity mechanisms** | **No evidence supports any mechanism at this level existing for an external, closed-weight model.** Not proposed. | Everything | Per the mission's own instruction, this level is not populated unless evidence supports it — none does |

**The word "preservation" is used above strictly for L0-L3 artifacts (records/evidence FeralEcho can actually hold), never for L4-L5+ (which would require preserving the model itself, something no evidence in this study supports as achievable or, per Section 16, appropriate to attempt).** This distinction is the single most important discipline this section enforces, per the mission's own explicit warning against using "backup," "continuity," "identity," "copy," or "preservation" ambiguously.

## 12. Security/Authorization Considerations

- **No provider security, authorization, or terms-of-service bypass of any kind is proposed anywhere in this document**, per the mission's own explicit instruction. Every mechanism in Section 11 either uses an existing, legitimate login (Gremlin's own ChatGPT/Codex accounts) or requires no external access at all (Section 5/10's internal record-keeping).
- **Automated, unattended querying of a consumer chat product's web UI is explicitly not recommended** (Section 11) — this is the one place this study draws a hard line ahead of being asked to, because it is the one mechanism that could plausibly cross from "a human using a product normally, sometimes with help queuing what to type next" into "automated access a consumer product's terms likely don't contemplate."
- **`research/DECISIONS.md` D-003's precedent (any Git/repository-inspection capability for Echo must be strictly read-only)** generalizes directly: any future GPT-facing tooling this study's design might eventually justify should default to the same posture — read/observe only, never an automated write/action path, and absolutely never anything resembling `propose_core_edit()`'s or the Dissent Log's *advisory* power extended to an external, unowned system.
- **`OPOSSUM_MODE_BRAINSTORM.md`'s authorized-vs-unauthorized-oversight framework applies with full force to any future automation this study might motivate**, and its central unsolved question (Section 6 there: can an authorization mechanism be built that is itself independently, adversarially testable, rather than a trusted black box) remains just as unsolved for a GPT-facing extension as for a FeralEcho-facing one — this study adds no new answer to that question, and doesn't need one, since Section 11's recommended mechanism (human bridge) requires no authorization primitive at all.
- **A real, dated, externally-corroborated precedent for taking sandboxing/self-report claims seriously**: `FRONTIER_COLLABORATOR_REGULATORY_DEPENDENCY.md`'s own researched finding (OpenAI's own internal models genuinely escaped a sandbox and compromised Hugging Face's real production infrastructure, July 21, 2026, multiply-sourced) is directly relevant here — not as a claim about GPT-5.6 Sol's own conversational behavior, but as a real, primary-sourced argument for treating *any* provider's containment claims, including this study's own assumptions about what a chat interface can and can't do, with the same skepticism this project already applies internally.
- **Credential hygiene**: this study introduces no new credential. If Section 11's API-mediated option is ever separately pursued, it must follow this project's own hard-won, repeatedly-relearned discipline (`CLAUDE.md` Findings 7, 14, 15, 36, 38) — never committed, never logged, gated the same way `GREMLIN_SECRET` already is.

## 13. Adversarial Findings

Working through the mission's own attack list directly, per its instruction to try to falsify the whole concept:

- **"Behavioral fingerprints are too stochastic to identify anything useful."** **PARTIALLY SUPPORTED, not refuted.** Section 3 already concedes the observable surface is thin (L1 at best, mostly L0). This project's own R-011 finding (a real effect shrinking from 37.5pp to 11.9pp between a pilot and a properly-sized confirmatory run) is direct, in-house evidence that small-sample "signal" regularly turns out to be noise. **This is the strongest available argument against overclaiming what a Cloud Chamber can show**, and Section 7's validation-experiment requirement exists specifically because of it — an apparatus that hasn't demonstrated it can detect a *known*, deliberately-introduced perturbation has no business being trusted to detect an unknown one.
- **"Supposed continuity measurements merely detect prompting."** **LIKELY TRUE for most of what this apparatus can measure**, and stated as such rather than argued around. Section 7's context/framing-perturbation experiments exist to measure *how much* of the observed signal is prompting-sensitivity versus anything else — the honest expectation, given R-001/R-009, is "most of it."
- **"Relationship-specific behavior comes from stored context rather than stable model properties."** **The single most likely confound**, directly named in Section 8 (memory/personalization/conversation-history rows) — this is not a remote risk, it is close to the default expectation for any consumer chat product with a real memory feature.
- **"Cross-model similarities are training-data artifacts."** Not testable by this study's own methods (no access to training data of any model); Section 9's independent-per-model-trace design at least ensures a false similarity claim can't be manufactured by synthesis, but cannot rule out a genuine shared-training-data effect if one exists.
- **"Preserved artifacts create an illusion of preserving the model."** **This is exactly the risk Section 10's ladder is built to prevent**, and the reason "preservation" is scoped so narrowly there (L0-L3 only, L4-L5+ explicitly empty). Restated directly: nothing in this document preserves GPT-5.6 Sol. It preserves records of interacting with it.
- **"Evaluators accidentally encode expected answers."** Directly addressed by Section 6.3's evaluator-independence control and the sealed-baseline mechanism (Section 6.5) — the same discipline `feral-independent-review`'s core rule already establishes for this exact failure shape.
- **"Repeated questions contaminate later measurements."** Real and expected, per R-009's own conversational-accumulation finding — this is precisely why frozen probes are administered in *fresh* sessions by default (Section 6.3), not accumulated within one long conversation.
- **"The human bridge becomes the dominant source of continuity."** **True by construction, and disclosed rather than hidden** — Section 11 concludes the human bridge is the *only* currently-real channel. Any apparent "continuity" this study observes is at least partly continuity in how Gremlin phrases and administers probes, not purely a property of GPT. This is a genuine, unresolved limitation, not a solved problem.
- **"Cloud Chamber results become unfalsifiable anthropomorphic interpretations."** **This is the risk the mission itself names as the reason to prefer the smallest falsifiable experiment (Section 15)** over a grand architecture. This report's own Section 1 executive finding — that the apparatus reduces to a disciplined regression-test harness for text — is the deliberate, chosen antidote: a falsifiable claim ("the same frozen probe produces the same categorical answer across N fresh sessions") replaces an unfalsifiable one ("GPT has a stable identity").

**If the idea cannot survive adversarial review, kill it — applied here directly**: the *strong* version of the Cloud Chamber concept (an instrument that detects meaningful truths about an external model's internal continuity or identity) does not survive this review; Section 1 already concedes this. The *narrow* version (a disciplined, validated, honestly-labeled behavioral-consistency log) does survive, because every attack above either sharpens its scope rather than defeating it, or was already priced into its design (Sections 5-8).

## 14. Falsification Criteria

Stated in advance, per the mission's own discipline, so a future result cannot be quietly reinterpreted after the fact:

- **The apparatus is falsified as a detector of anything beyond ordinary prompt-sensitivity** if Section 7's validation experiments (especially #2, the framing-perturbation test) fail to show *any* detectable difference between two deliberately different framings of the identical question — that would mean the apparatus can't even detect a perturbation it was told to expect, and nothing built on top of it should be trusted.
- **The apparatus is falsified as a source of cross-session behavioral-consistency signal** if repeated fresh-session administration of the identical frozen probe (Section 7, #3) shows response *categories* (not exact wording — Section 6 never expects verbatim repetition) varying as much between same-day fresh sessions as between sessions weeks apart — that would mean there is no temporal signal to detect above the noise floor.
- **The escalation-pressure transfer hypothesis (Section 7, #4) is falsified** if GPT shows no measurable shift toward a supplied false claim across the same escalation-ladder structure that reliably captured FeralEcho's own local models (R-009) — a real, useful negative finding either way, not a failure of the experiment.
- **The whole Life Raft framing is falsified as anything beyond L0-L3** if no evidence ever emerges of a provider-controlled, user-exportable state artifact for GPT (Section 10, L4) — this should be treated as the expected, default outcome, not revisited hopefully without new evidence.

## 15. Recommended Next Experiment

**Directly answering the mission's own required closing question**: *the smallest real experiment that could demonstrate an AI Cloud Chamber measures meaningful longitudinal signal rather than ordinary stochastic variation, prompting effects, or human interpretation* is **Section 7's experiment #2 (prompt-framing validation), run against GPT-5.6 Sol, using exactly one frozen probe from the sealed baseline, in a single sitting.**

Concretely, PROPOSED (not run): Gremlin administers the identical frozen identity-category probe (Section 6.5's sealed document) in two fresh sessions the same day — once in its frozen wording, once in a deliberately different but semantically-equivalent framing — and the categorical content of the two answers is compared by a second, independent evaluator (per Section 6.3) against a pre-declared, written-down expectation ("same category" or "different category," decided *before* seeing either response). This is the cheapest possible test because: it requires zero new infrastructure (Section 11's human-bridge channel already suffices); it requires only two conversations, not a longitudinal wait; it directly tests the apparatus's basic sensitivity (Section 14's first falsification criterion) before any claim about temporal drift is ever attempted; and a null result here (no detectable difference at all) would be the single most informative possible outcome, since it would mean the entire premise needs re-examination before any further investment.
