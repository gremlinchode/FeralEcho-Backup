# AP-0 v2 — Causal-chain bypass analysis and adversarial (skeptic) review

Labels: **OBSERVED** (read/run this session), **INFERRED** (reasoned), **DESIGN** (a control specified for Stage 1 v2; not yet run). Nothing here is a result about learning.

## Part A — Arrow-by-arrow bypass analysis

Intended chain: **experience → constructor → candidate artifact → independent evaluation → retention decision → persistent artifact → fresh-process reload → behavioural consequence on sealed novel tasks.**

### A1. experience → constructor
- *What crosses:* deterministic environment episodes generated by the harness from the (secret) convention, plus the public task-type context and the constructor instruction. (OBSERVED in `constructor.py`.)
- *Bypass candidates and status:*
  1. **Constructor prior knowledge** (model-native): tokens are screened non-words, so the value of a code/tag/event cannot be guessed from the token. Chance-level guesses exist (K1: 1 in 3 per code). QUAL-1's A1 variant measures fabrication directly. **Control: DESIGN/QUAL.**
  2. **Hidden test/evaluator information reaching the constructor:** the constructor runs through `run_gen.py` in a kernel jail with no read access to the oracle; request texts are scanned for hidden-case literals at build time; qualification and Stage 1 worlds use disjoint token sets (asserted). **OBSERVED (verify suite).**
  3. **The harness does part of the induction.** *This is a real weakness, not a bypass to be closed:* the harness chooses episodes that identify the convention (brute-force verified) and supplies the schema through the public task-type text ("ties are resolved by the site's tag priority"). The system therefore learns **parameters of a schema it is told about**, from **experience someone else selected**. This bounds the claims (see Part C): no "autonomous experience selection", no "concept formation".
  4. **R1 display grouping** (episodes grouped by token) is a deterministic reformatting; it does not state a rule. INFERRED to be a mild aid; QUAL-1 reports R0 and R1 separately so the aid is visible rather than hidden.
- *Residual:* none that a control can remove; (3) is a scope limit.

### A2. constructor → candidate artifact
- *What crosses:* one text draft (≤1200 chars after whitespace normalization), hash-recorded in a hash-chained ledger. Nothing else. **OBSERVED design.**
- *Bypass:* the draft could smuggle information (e.g. a copy of a test) only if the constructor had it (A1.2 forbids). **Closed by A1.2.**

### A3. artifact → independent evaluation
- *Evaluator independence:* the gate uses the **worker** (a different call, different prompt, different process from the constructor) and the **oracle** (hidden tests, nonce-graded, kernel sandbox), on **validation** tasks whose hidden cases come from a stream disjoint from the sealed test stream. The constructor never sees validation tasks or verdicts beyond accept/reject counts. **OBSERVED in `qual.py` (validation partition, jails).**
- *Bypass candidates:*
  1. **Selection on validation** (winner's curse): at most 3 drafts are compared, on 4 tasks; effect on the sealed test is small but non-zero. **DESIGN:** report the number of drafts tried; FAILED-DRAFT is the matched counter-example drawn from the same process.
  2. **Worker/constructor are the same weights** in QA: a draft in the model's own style may be easier for it to use than hand-written text. **DESIGN:** Stage 1 keeps H (hand-written) beside P; a P > H result would be flagged as a style effect, not an acquisition effect; a constructed-style NEUTRAL (foreign-convention draft built by the same pipeline) is added **only if** Stage 0's null NEUTRAL (0.000) is not reproduced on sealed tasks.
- *Residual:* the oracle is external and human-authored; "independent" means independent of the generator and constructor, not of the experimenter.

### A4. retention decision → persistent artifact
- *What crosses:* the accepted draft's text and hash, written to a carrier file by the orchestrator; the rejected draft (first failing) is stored as the FAILED-DRAFT carrier. **DESIGN.**
- *Bypass:* orchestrator state (in-memory verdicts, previous responses) could leak if acquisition and evaluation shared a process. **DESIGN control:** acquisition, gate, and each evaluation arm are **separate processes**; only carrier files (hash-recorded) cross; evaluation arms run in kernel jails that cannot read acquisition ledgers.

### A5. persistent artifact → fresh-process reload
- *The boundary that must be evidenced,* not asserted. **DESIGN evidence per run:** (i) carrier file SHA-256 identical before and after; (ii) evaluation process PID and start time later than the acquisition process's exit time, different from every earlier process; (iii) the jail profile hash; (iv) the exact request body of every call (system + user text and seed) so the only cross-boundary information channel is demonstrably the carrier text; (v) model unloaded between acquisition and evaluation (`keep_alive` 0) so no loaded-model residue exists (weights are frozen and the API is stateless in any case).
- *Bypass candidates:* Ollama KV/prefix caching (**INFERRED** to change latency only; generation is deterministic per token sequence: 8/8 same-seed probes identical, OBSERVED Stage 0); process-environment variables (jail + `python -I`); file names/paths (never placed in prompts); task ids (never in prompts, OBSERVED request re-derivation).

### A6. reload → behavioural consequence on sealed tasks
- *Bypass candidates and controls:*
  1. **Sealed-test exposure to acquisition:** sealed worlds and tests are derived from `SHA-256("AP0-S1" ‖ v2-prereg-hash ‖ Stage-0-evidence-hash)` **after** the v2 freeze and are not materialized on disk until acquisition has finished and carriers are hashed (exposure log). **DESIGN.** No sealed material exists now.
  2. **Prompt structure differences across arms:** identical system/user templates; only the carrier block differs (re-derived and hashed per call). NEUTRAL/MISMATCH are exactly length-matched to H (OBSERVED Stage 0); P differs in length and style (reported).
  3. **Scaffold effect:** Stage 0 found no scaffold effect on T/S (NEUTRAL−N = 0.00) but a +0.39 effect on the NEAR set (small n, post hoc). **DESIGN:** NEUTRAL is the baseline for every negative-control contrast; NEAR grown to 18 tasks.
  4. **Evaluator leakage:** nonce grading; hidden tests unreadable by arm jails (OBSERVED). **Memorization:** test inputs disjoint from episodes and validation cases (OBSERVED checks); structurally changed tasks (S) report transfer separately.
  5. **Production memory / RiverBrain / FAISS / routing:** not imported (static + dynamic audit, OBSERVED); Ollama is stateless per request.
  6. **Experience-swap control (DESIGN, closes "prior/scaffold, not experience"):** each convention has two realizations (a, b). Carriers built from a's episodes and b's episodes are each evaluated on **both** worlds' tasks. If the carrier content is truly determined by the experience, each helps on its own world and fails on the other (double dissociation). A carrier that helps both worlds equally is not experience-specific.

## Part B — The skeptic's strongest attack, and what Stage 1 can and cannot separate

> "You built an elaborate mechanism that merely converts examples into prompt instructions, then showed that an LLM follows instructions. The model learned nothing: a human supplied the schema, picked the episodes, wrote the validation tasks and the oracle. The 'retained state' is a text file. This is a database of instructions plus a pipeline that fills in a few parameters."

**Grant everything that is true in it.** Weights never change (SCOPE, stated from the start). The harness supplies the schema (public task-type text), the episodes (chosen to identify the convention), the applicability line, the validation tasks and the oracle. Stage 0 already showed the worker follows a stated procedure (H 0.815 vs 0.000): that is ordinary in-context instruction following, and by itself says nothing about learning. Whether "persisting a file" counts as retention of *competence* is a definitional choice; the experiment must not use vocabulary to win it.

**Five things a Stage 1 outcome could be, and what would tell them apart:**

| # | Alternative | What would distinguish it | Can Stage 1 v2 distinguish it? |
|---|---|---|---|
| 1 | Ordinary in-context instruction following | Already shown by H (Stage 0). Stage 1 contributes nothing new here. | Not the question; H is the reference |
| 2 | Offline summarization of examples (a one-off compression step) | Whether P beats **IC** (the same episodes inline) and **E** (raw episodes retained). If P ≈ IC ≈ E the constructor added nothing beyond restating usable text; if P ≫ IC/E, the offline induction step does real work the worker cannot do in one pass (this is what Stage 0's E/IC ≈ 0.25 makes possible). | **Yes, partially**: it shows the constructor step adds capability; it cannot show the step is "learning" rather than "compilation" — that is definitional. |
| 3 | Persistent storage of *externally supplied* knowledge | The content of P must be a function of the experience: (a) experience-swap double dissociation; (b) A1 (missing evidence → hedge, not invent); (c) no path from oracle/human to the constructor (jail, leak scan). | **Yes**, for the specific claim "the convention did not come from anywhere except the episodes". It cannot exclude that the *schema* was supplied. |
| 4 | Experience-dependent construction of retained actionable state | (2) and (3) together, plus that retention is decided by an evaluator that did not generate the draft (P > FAILED-DRAFT). | **Yes, at pilot scale** — this is the strongest thing Stage 1 can support. |
| 5 | Persistent acquired behavioural competence | Fresh-process reload (yes), structural transfer S (yes), **longer-term** persistence (no), **accumulation** (no — Stage 2), competence beyond lookup-style conventions (no: K1 is a table, K2 an ordering, K3 an operation table; these are knowledge-like more than skill-like). | **Only in a narrow sense**; the label "competence" must be replaced by "acquired convention knowledge, applied to new inputs and new task shapes". |

**What Stage 1 cannot distinguish (stated so the terminology cannot outrun evidence):**
- learning versus compilation/caching of examples (definitional);
- whether the system could have *chosen* or *generated* its own experience (the harness chooses);
- whether the schema was learned (it is supplied);
- weight-level learning (none occurs);
- durability beyond one fresh process (no multi-day test);
- accumulation (Stage 2; a single-cycle acquisition cannot show it);
- any inheritance / minimum-state question.

**Do not inflate.** If Stage 1 succeeds, the honest sentence is: *"For three invented conventions, a frozen 7B model, given episodes that identify the convention, produced a text procedure that an independent evaluator validated, that persisted across a process boundary, and that let the same frozen model solve new tasks (including structurally changed ones) that it otherwise fails — and the content was demonstrably determined by the episodes."* That is real and modest. It is not "FeralEcho learned" in any general sense.
