# Frozen Experimental Contract

Written and hashed BEFORE any TRAIN or HELD-OUT instance is generated. Per this mission's own stop conditions, nothing below may change after the held-out set is sealed (§Phase 2) except by declaring the run an APPARATUS FAILURE.

- **Model:** `qwen2.5-coder:7b`, unmodified, via `app/experiments/minimal_procedure_transfer/ollama_client.py` (reused, unmodified).
- **Task family / difficulty:** `extract_code`, Level 3, from `app/experiments/historical_difficulty_calibration/tasks.py::build_calibration_set(seeds, level=3, prefix)` (reused, unmodified).
- **Prompt:** the CORRECTED prompt from `historical_difficulty_calibration/run_calibration.py::build_prompt(task)`, extended with exactly one new, optional, empty-by-default parameter (`context: str = ""`) inserted at a single fixed point (immediately before the final "Write the function `solve` now" instruction). With `context=""`, the extended function MUST produce byte-identical output to the original qualified `build_prompt(task)` — verified in `run.py` before any real call is made, and reported in the final report. This is the only change made to the corrected prompt; its own already-qualified text is not otherwise reworded.
- **Evaluator:** `app/experiments/minimal_procedure_transfer/sandbox.py::run_candidate()` (reused, unmodified), exact-string-match against the construction-time-known `expected_code`.
- **Sampling:** `temperature=0`, `top_p=1.0`, `seed=20260923`, `num_predict=700`, `num_ctx=4096` (identical to the qualified calibration run — `ollama_client.py` is not modified).
- **TRAIN episodes:** 8 fresh Level-3 instances, seeds 1000-1007. Each instance gets one first attempt; on F2 failure, exactly one retry with real, mechanically-generated F2 failure feedback (`sandbox.format_failure_feedback()`, reused unmodified) appended to the same task's prompt — mirroring the prior `minimal_procedure_transfer` pilot's own already-used experience-episode shape. No further retries beyond one. Every attempt (first and retry) is logged in full.
- **HELD-OUT instances:** 10 fresh Level-3 instances, seeds 1100-1109 — mutually disjoint from the TRAIN seed range and from every calibration/evaluator-qualification seed already spent (700-704, 800-804, 810-814, 820-824, 830-834, 840-844, 850-854). The complete held-out set is generated and its SHA-256 commitment recorded BEFORE any TRAIN episode is run.
- **Arms:** P (frozen, TRAIN-derived procedure), G (fixed, generic-tip counterfeit, hand-authored, no TRAIN-specific content), Z (zero teaching, `context=""`, byte-identical to the qualified calibration prompt). No N arm — per the governing mission's own "P/G/Z are mandatory, do not add arms merely because more complexity looks rigorous" instruction, and because G already targets the specific confound (generic instruction-following benefit) an N arm would otherwise help isolate.
- **Scoring:** F2 pass/fail per `sandbox.run_candidate()`'s own `passed` bool. Primary outcome: held-out pass rate per arm. Secondary: failure-class breakdown (reusing `historical_difficulty_calibration/run_calibration.py::classify_failure()`, unmodified) and the pre-declared consumption-signature check (Phase 15, declared after procedure freeze, before held-out execution).
- **Retry policy, held-out phase:** none. One attempt per (instance, arm). No retries, no selective dropping, no post-hoc prompt repair.
- **Stopping rule:** if any Phase-13-equivalent apparatus-integrity check fails (held-out hash mismatch, procedure hash mismatch, a held-out instance's seed found to overlap any prior seed range), STOP immediately and report APPARATUS FAILURE rather than repairing and continuing under the same run.
- **Statistical analysis:** paired exact McNemar test (binomial test on discordant pairs, two-sided reported, one-sided interpretation stated separately) for P-vs-Z and P-vs-G; raw pass rates and 95% Wilson confidence intervals reported for all three arms; effect size as the raw percentage-point difference. p<0.05 is not treated as proof of learning; p>0.05 is not treated as proof of no effect — both stated explicitly in the report given the small, pilot-scale sample.
- **Procedure-extraction rule:** performed once, after all 8 TRAIN episodes complete, by this investigator directly summarizing only the concrete, observed pattern of what failed and what succeeded across the real TRAIN attempts (never a general algorithmic fact asserted independent of that evidence). Every substantive clause in the frozen procedure must be traceable to a specific TRAIN episode's own real observed outcome. Frozen (hashed, timestamped) immediately after derivation; no edits permitted afterward for any reason, including a poor held-out result.
- **Treatment ordering:** for each held-out instance, the three arms are run in the fixed order P, G, Z (declared here, before any held-out call, so this is not chosen post hoc to favor any arm) — this ordering has no mechanical way to bias outcomes, since each arm's call is a fully independent, fresh, single-turn request with no shared state, memory, or history across arms or across instances (verified structurally, not merely asserted, in the final report's §16).
- **Exclusion rules:** none. Every TRAIN and HELD-OUT attempt, pass or fail, malformed or not, is recorded and counted. No instance is ever dropped after generation.
